# 用户关怀触达模板过渡记录

## 目的

在站内信模板管理完善前，先记录人工/批量邮件的模板类别和触达状态，避免同一用户重复收到相同提醒。正式模板后续应迁移到站内信模板库，并复用相同的类别标识和去重规则。

| 类别 | 活动标识 | 用途 |

用户可以命中多个原始类别，但一次触达只能选择一个主类别。主类别优先级应以故障协助、高价值召回、普通激活的顺序确定；财务提醒不纳入本方案。

`active_low_balance` 和 `payment_abandoned` 仅保留测试历史，不进入正式模板库，也不参与用户触达。余额不足仅在用户主动查看账户或请求因余额无法继续时按现有业务规则展示，不额外发送关怀邮件或站内信。

## 文案优化版

以下文案作为站内信模板的优化版语气基线，对应 `*_v2` 模板。内部类别名只用于筛选和去重，不直接展示给用户。

所有模板统一以“亲爱的用户，您好”开头；存在用户昵称时，可以替换为“亲爱的 {{recipient_name}}，您好”。正文避免使用“监测到”“命中规则”等内部表达。

优化版本的 `template_key` 统一使用对应类别加 `_v2`；此前发送的 `v1` 预览记录继续保留，便于比较效果。

对用户只呈现与当前帮助直接相关的信息，不展示后台筛选依据、失败次数、登录时间、历史消费排名或“我们一直在观察您”的暗示。涉及金额、订单和订阅时，只展示用户需要确认的必要字段。

## 正式模板方向

主题建议：`使用过程中遇到问题了吗？我们来帮您`

正文应包含：

- 亲切说明“账户累计充值后暂未发现成功调用记录”；
- 展示累计充值金额，不使用“本次充值”等容易造成误解的表述；
- 询问用户是否在访问凭证、模型/分组或请求配置环节遇到问题；
- 提供工单和接入文档入口；
- 提醒用户不要提交完整 API Key；
- 明确说明暂时未使用可以忽略，不制造催促感。

## 建议变量

- `recipient_name`
- `total_recharged`
- `current_balance`
- `last_success_at`
- `support_url`
- `docs_url`

金额和状态只能来自发送时的用户数据。模板预览必须明确标识为测试，不得被当成真实账单或充值通知。

## 触达与去重规则

- 每封正式邮件记录 `channel=email`、`category`、`campaign_id`、`template_key`、发送状态和用户 ID。
- 同一用户同一 `category + campaign_id` 只发送一次。
- 同一用户同类关怀默认 30 天内不重复发送，新活动也必须经过冷却检查。
- 测试邮件使用独立类别，不计入正式触达历史。
- 用户最近已经成功调用、账户被删除或已明确退订时，不发送该关怀模板。
- 邮件属于可选关怀通知，正式模板功能必须支持退订；站内信保留独立的已读状态。
- 不发送余额不足、未完成支付或其他催促充值性质的邮件与站内信。
- 不在邮件中展示上游域名、账号信息、完整 API Key 或其他用户数据。

## 当前过渡实现
